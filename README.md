# 🎓 منصة مستويات الطلاب

منصة ويب كاملة بالعربي (RTL) لإدارة الطلاب ومستوياتهم ودروسهم.

- **الباك إند:** Node.js + Express + SQLite
- **الفرونت إند:** HTML/CSS/JavaScript عادي (من غير build tools)
- **الكاش:** طبقة `localStorage` في المتصفح + رقم إصدار للبيانات

> البيانات الأساسية بتتحفظ في قاعدة بيانات SQLite على السيرفر، والكاش في المتصفح
> مجرد طبقة سرعة/احتياطي عشان الصفحات تفتح بسرعة وتشتغل لو النت قطع لحظة.

---

## التشغيل

```bash
cd student-platform
npm install
npm start
```

افتح: <http://localhost:3000>

للتطوير مع إعادة تشغيل تلقائي:

```bash
npm run dev
```

> محتاج Node.js إصدار **22.5 أو أحدث** (لأن المشروع بيستخدم `node:sqlite` المدمج).

### حسابات البداية

| الحساب | الباسورد | الصلاحية |
|---|---|---|
| `admin` | `admin123` | مدير |
| `student1` | `123456` | طالب (المستوى الأول) |

⚠️ **غيّر باسورد المدير فورًا** بعد أول تشغيل:

```bash
npm run passwd -- admin "باسورد-قوي-جديد"
```

نفس الأمر بيشتغل لأي حساب تاني وبيقفل كل جلساته القديمة.

## المميزات

### المدير
- إنشاء حساب طالب (اسم ظاهر + يوزر + باسورد + مستوى).
- تعديل اليوزر/الباسورد/المستوى في أي وقت.
- إيقاف/تفعيل حساب طالب (الإيقاف بيقفل جلساته فورًا).
- حذف طالب.
- إضافة/تعديل/حذف المستويات والدروس.
- تبويب «الدروس» مستقل لإدارة كل دروس المستوى من مكان واحد، مع فلتر بالمستوى.
- شيت درجات إلكتروني (طلاب × تقييمات): تعديل الدرجات مباشرة، حساب المجموع والنسبة
  لكل طالب أوتوماتيك، حفظ الكل مرة واحدة، وتصدير Excel/CSV.
- رفع محاضرات/ملفات لأي درس (PDF، Word، PowerPoint، Excel، صور، فيديو، صوت، ZIP).
- حذف المرفقات وتحميلها.
- عمل تقييمات/امتحانات لكل مستوى وتحديد الدرجة النهائية.
- رصد وتعديل ومسح درجة كل طالب، مع منع أي درجة أكبر من النهاية.
- البحث في الطلاب بالاسم أو اليوزر أو المستوى.
- صفحة «حسابي» لتغيير بياناته وباسوره.

### الطالب
- دخول باليوزر والباسورد.
- يشوف مستواه الحالي ودروسه بس (مش مستويات حد تاني).
- يفتح الدرس ويقرأ محتواه، ويشوف رابط الفيديو لو موجود.
- يحمّل مرفقات درسه (محاضرات/ملفات) من غير ما يقدر يشوف ملفات مستوى تاني.
- يعلّم الدرس كـ «تم» أو يلغيها، ويشوف نسبة تقدمه وشريط التقدم.
- يشوف درجاته في كل تقييم ومتوسطه المرجّح.
- يغيّر اسمه الظاهر، ويوزره (بتأكيد الباسورد)، وباسوره.
- بعد تغيير الباسورد، كل الجلسات التانية بتتقفل.

### تقدم الطالب
- التقدم محفوظ في جدول `lesson_progress` (صف لكل طالب/درس).
- نسبة التقدم بتتحسب من دروس المستوى الحالي بس.
- لو الطالب اتنقل لمستوى تاني، الدروس القديمة مش بتتحسب في نسبته الجديدة.
- لو درس اتحذف، سجل إنجازه بيتمسح معاه تلقائيًا.
- المدير بيشوف نسبة كل طالب في جدول الطلاب.

### الدرجات والمرفقات
- التقييمات في جدول `assessments` ودرجات الطلاب في جدول `grades`.
- متوسط الطالب بيتحسب بأوزان الدرجات النهائية للتقييمات اللي اترصدت بس.
- التقييم اللي لسه مترصدش بيظهر للطالب بعلامة «—» بدل ما يختفي.
- المرفقات في جدول `lesson_files`، والملف الفيزيائي في `data/uploads/`
  باسم عشوائي — الاسم الأصلي محفوظ للعرض والتحميل.
- أنواع الملفات محدودة بقائمة آمنة (مفيش exe/html/js/svg)، والحد الأقصى 50 ميجا.
- حذف ملف/درس/مستوى بيمسح الملفات الفيزيائية معاه.

## قاعدة البيانات

الملف: `data/app.db` (بيتولد تلقائيًا أول تشغيل مع بيانات تجريبية).

| الجدول | وظيفته |
|---|---|
| `users` | الطلاب والمدير: يوزر، hash باسورد، مستوى، حالة التفعيل |
| `levels` | المستويات (الاسم، الوصف، الترتيب) |
| `lessons` | الدروس التابعة لكل مستوى |
| `lesson_progress` | الدروس اللي كل طالب خلّصها (طالب + درس + وقت الإنجاز) |
| `lesson_files` | مرفقات الدروس (الاسم الأصلي + اسم التخزين + الحجم + النوع) |
| `assessments` | التقييمات/الامتحانات التابعة لكل مستوى ودرجتها النهائية |
| `grades` | درجة كل طالب في كل تقييم (صف واحد لكل طالب/تقييم) |
| `sessions` | جلسات الدخول (hash التوكن + وقت الانتهاء) |
| `meta` | رقم إصدار البيانات المستخدم في الكاش |

- حذف مستوى → دروسه وتقييماته وملفاته بتتمسح معاه، والطلاب بيرجعوا «بدون مستوى».
- حذف درس → تقدمه وملفاته بتتمسح معاه (والملفات من القرص كمان).
- حذف تقييم → درجاته بتتمسح معاه.
- حذف طالب → جلساته ودرجاته وتقدمه بيتقفلوا/بيتمسحوا تلقائيًا.

### نسخة احتياطية

أوقف السيرفر وانسخ فولدر `data/` كامل (فيه `app.db` وأحيانًا `app.db-wal` و`app.db-shm`
وفولدر `uploads/` اللي فيه مرفقات الدروس).
أو استخدم:

```bash
sqlite3 data/app.db ".backup backup.db"
```

## الكاش في المتصفح — إزاي بيشتغل؟

1. كل طلب `GET` ناجح بيتخزن في `localStorage` تحت `sp:cache:v1:*`.
2. السيرفر عنده `data_version` في جدول `meta`، وبيزوّده مع **أي** تعديل عام
   (طالب/مستوى/درس/تقييم/مرفق).
3. أول ما الصفحة تفتح، بتسأل `/api/data-version` وتقارن الرقم المخزّن.
   - لو مختلف → بتمسح الكاش كله وتجيب بيانات جديدة.
   - لو نفس الرقم → بتكمل عادي.
4. لو الشبكة قطعت، `api.js` بيرجّع آخر نسخة محفوظة بدل ما الصفحة تفشل.
5. الكاش عمره 5 دقايق كحد أقصى، وبعدها بيتجاهله حتى لو مفيش اتصال.

حالة تقدم الطالب بتتحدّث في الكاش فورًا بعد أي تعليم/إلغاء من غير reload،
ومش بتزوّد «إصدار البيانات» لأنها خاصة بكل طالب لوحده.

يعني: تعديل من أي جهاز بيظهر عند الباقي بمجرد تحديث الصفحة.

| GET/POST | `/api/admin/levels` | عرض/إضافة مستوى (مع دروسه وتقييماته ومرفقاته) |
| PATCH/DELETE | `/api/admin/levels/:id` | تعديل/حذف مستوى |
| POST | `/api/admin/lessons` | إضافة درس |
| PATCH/DELETE | `/api/admin/lessons/:id` | تعديل/حذف درس |
| POST | `/api/admin/lessons/:id/files` | رفع مرفق للدرس (`multipart/form-data` باسم `file`) |
| DELETE | `/api/admin/files/:id` | حذف مرفق |
| POST | `/api/admin/assessments` | إضافة تقييم |
| PATCH/DELETE | `/api/admin/assessments/:id` | تعديل/حذف تقييم |
| GET | `/api/admin/students/:id/grades` | درجات طالب مع كل تقييمات مستواه |
| GET | `/api/admin/levels/:id/sheet` | شيت الدرجات الكامل (طلاب × تقييمات) |
| POST | `/api/admin/levels/:id/grades` | حفظ شيت الدرجات مرة واحدة `{ grades: [...] }` |
| POST | `/api/admin/grades` | رصد/تعديل/مسح درجة (`score: null` بتمسحها) |

## الأمان — إيه اللي معمول؟

- الباسورد بيتخزن بـ `scrypt` + salt عشوائي لكل مستخدم، ومفيش أي باسورد نص صريح.
- الجلسة في كوكي `HttpOnly` + `SameSite=Lax`، والتوكن نفسه مش مخزّن في الداتابيز
  (بنخزّن `sha256` منه بس).
- محاولات الدخول الغلط محدودة: 6 محاولات لكل IP+يوزر، وبعدها قفل 10 دقايق.
- التحقق من `Origin` في كل طلب بيغيّر بيانات (طبقة CSRF).
- كل النصوص بتتعرض بـ `textContent` مش `innerHTML` (حماية من XSS).
- روابط الفيديو لازم تبدأ بـ `http/https` بس.
- المرفقات: أسماء تخزين عشوائية، امتدادات مسموحة بس، حد 50 ميجا،
  والتحميل محمي — الطالب بيحمّل ملفات مستواه فقط.
- ملفات الرفع بتتحفظ في `data/uploads/` ومش بتتعرض كملفات ثابتة من Express.
- رسائل الخطأ عامة عشان متكشفش هل اليوزر موجود ولا لأ.
- تغيير/إيقاف حساب من المدير بيقفل جلسات الطالب فورًا.

### حدود معروفة
- قفل المحاولات في الذاكرة، فلو شغّلت أكتر من نسخة على سيرفرات مختلفة
  كل نسخة هيبقى عندها عدّاد لوحده.
- من غير HTTPS، الكوكي مش هيكون `Secure`. على الاستضافة الحقيقية شغّل
  `NODE_ENV=production` خلف Reverse Proxy بيدعم HTTPS.
- مفيش استعادة باسورد بالإيميل؛ المدير بيعملها من التيرمنال (`npm run passwd`).

## النشر السريع

1. ارفع المشروع على سيرفر فيه Node 22.5+.
2. `npm install --omit=dev`
3. `NODE_ENV=production PORT=3000 npm start`
4. حط Nginx أو Caddy قدامه مع HTTPS، وخلي `data/` على قرص ثابت وليها نسخ احتياطي.
5. غيّر باسورد `admin` الافتراضي قبل أي حاجة.

## اختبارات اتعملت على المشروع

- 32 اختبار API: دخول/صلاحيات، إنشاء وتعديل وحذف طالب، منع التكرار والمدخلات
  الغلط، تغيير الباسورد واليوزر، إدارة المستويات والدروس، وحماية المسارات.
- 24 اختبار تقدم الطالب: تعليم/إلغاء درس، صحة النسبة، منع تعديل درس مستوى تاني،
  احتساب النسبة بعد حذف درس، وظهورها في جدول المدير.
- 39 اختبار للمرفقات والدرجات: رفع PDF واسم عربي، منع exe، حد الصلاحيات،
  تحميل الطالب الصحيح ومنع مستوى تاني، حذف الملف من القرص، حذف درس/مستوى
  بيمسح ملفاته، رصد/تعديل/مسح درجة، منع تجاوز النهاية، ومتوسط الطالب.
- 23 اختبار للشيت الإلكتروني: تحميل الشيت، حفظ دفعة درجات مرة واحدة، تعديل خلية،
  مسح الدرجات، منع طالب/تقييم من مستوى تاني، منع تجاوز الدرجة النهائية،
  وحماية الشيت من الطلاب.
- اختبار يدوي في المتصفح: تسجيل دخول المدير، إضافة طالب، فتح درس، تغيير باسورد،
  تحديث الكاش تلقائيًا بعد تغيير مستوى الطالب، وتعليم الدرس مع تحديث النسبة.
